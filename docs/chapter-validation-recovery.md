# Chapter validation recovery: local validation

This focused change is based on freshly fetched main
`32a16782f95d884480585fb9ffad64e1abd34196`, on isolated branch
`codex/chapter-validation-recovery`.

The code establishes that chapter `validation_source` failures previously bypassed bounded
application correction. A successful SDK return is not a validated chapter response. A discarded
real response cannot reveal whether wording, references, quotation anchors or another source
constraint failed; no live violation is attributed to any one check.

## Delivered behavior

- Structurally valid, fully covered chapter responses with invalid passage wording can receive
  one correction when request retries are nonzero. It must retain passage order/count/kinds,
  unit references and all omissions/reasons, then pass the unchanged source validator.
- Invalid references/order/kinds and mixed wording plus missing coverage remain terminal source
  failures. Refusals/truncation do not receive chapter source correction. Schema/coverage
  recovery keeps its existing bound. No deterministic fallback or partial-complete result is used.
- Safe diagnostics distinguish fixed chapter reasons and numeric chunk/passage/unit locations;
  word-sequence failures also report token counts and a first mismatch index. They include no
  testimony, rejected bodies, secrets or arbitrary IDs.
- Admission cancellation propagates as stopped/incomplete instead of becoming a generic chapter
  failure. Successful checkpoints remain available for resume. Terminal validation failures
  count once, correction calls count as requests, and returned usage is counted before validation.
- Initial prompts, schemas, accepted-output rules and base settings/checkpoint fingerprints are
  unchanged. The correction instruction explicitly clarifies exact unit concatenation and
  quotation/apostrophe anchors, which broad punctuation wording in the initial prompt can obscure.

Both requested styles still publish in one atomic bundle. Independent interview publication
would require explicit per-style status, transaction and resume semantics. This change preserves
that integrity boundary. An explicitly selected interview-only draft remains available as a
separate deterministic output; it does not complete a failed narrative or clear human review.

grouping, kind and reference changes during repair; valid explicit omissions and third person;

accepted/rejected decisions and accepted output matched. All style/person settings fingerprints
matched. A checkpoint generated by main's chapter module was reused without provider requests
